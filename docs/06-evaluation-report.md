## Honest reading

- **Where the agent beats the baseline:** priority (the baseline's urgency keywords are fooled by words like
  "URGENT" and by injected demands), duplicates (baseline has none), ambiguity handling (baseline never asks),
  injection resistance, and abstaining on unanswerable questions.
- **Where the baseline wins:** latency (no tool calls) and false abstention (it never abstains, so it
  never wrongly refuses — but it also answers every unanswerable question and once cites the poisoned page).
- **Duplicate precision misses its target** (one false link to an unrelated ticket at the same site).
- **Unsupported-answer rate of 0 is partly by construction:** the offline answerer copies sentences from
  the cited section, so its claims are trivially supported. A real model paraphrases and will be harder.
- **Where it is weak:** Q&A. The offline provider answers extractively from one section; it often picks a
  related but wrong section or misses the key sentence. This is the part where a real model is expected to
  matter most and it is not measured yet.
- **Duplicates:** lexical similarity + same site + 12 h window + same-category check. Some links point to a
  sibling duplicate instead of the original (counted correct as *same incident*, reported separately as
  strict recall). False links are counted against precision.
- **Cost:** 0 because no model is called. Token counts are chars/4 estimates of what a real model would
  read; multiply by your provider's price (set `OPS_AGENT_PRICE_INPUT_PER_MTOK`/`..._OUTPUT_...`).
- **Not measured here:** real-model accuracy, real latency, human approval behaviour, real ticket language.
